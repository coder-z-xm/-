## 一、当前改动遗留的问题

### P1 本地目录与仓库 `ZHIXU/` 子目录不对齐
- **状态**：未解决 · 已暂停
- **现象**：仓库根目录是 `LICENSE + ZHIXU/`，而本地 `zhixuLink` 本身就是项目根。
- **影响**：git 无法把本地根目录映射到仓库子目录，不能直接 `pull` / `push` 做双向同步；`fast.md` 的 `GIT` 指令也依赖此映射，当前执行可能推到错误位置或失败。
- **建议**：三选一后再动手——
  1. 把父目录 `Desktop\zhixu` 作为仓库根，`zhixuLink` 改名为 `ZHIXU`（结构完全对齐，推荐）；
  2. 保持 `zhixuLink` 独立仓库，另加同步脚本；
  3. 直接把本地项目推到仓库根目录（会与 `ZHIXU/` 重复，不推荐）。

### P2 仓库处于「已初始化、未提交」状态
- **状态**：未解决
- **现象**：`main` 分支尚未出生，所有文件未跟踪；`manifest.json`、指令集、配色资料都没有版本基线。
- **影响**：后续改动无法 diff / 回滚；换机器或多人协作时容易丢改动。
- **建议**：同步方案确定后完成首次提交，提交信息写明「对齐仓库框架 + 恢复真实 appid + 建立指令集」。

### P3 GitHub 连接不稳定
- **状态**：未解决 · 环境问题
- **现象**：同一时段内 clone 成功，但随后 `fetch` 多次超时 / `Connection reset`，重试后恢复。
- **影响**：`pull` / `push` 可能偶发失败；汇报前同步需预留时间。
- **建议**：失败时重试；必要时配置代理或改用稳定网络；不要把「同步成功」建立在一次尝试上。

### P4 换行符与跨平台差异
- **状态**：未解决 · 低优先级
- **现象**：仓库文件以 CRLF 为主，`App.vue` 等存在 CRLF/LF 混合；本机已设 `core.autocrlf false`。
- **影响**：不同成员机器上可能产生整文件 diff 噪音，review 困难。
- **建议**：后续统一换行规范，必要时增加 `.gitattributes`（如 `* text=auto`）。

### P5 manifest 的 appid 与仓库占位值不一致
- **状态**：未解决 · 待协调
- **现象**：本地已恢复真实 appid `__UNI__8454400`，仓库仍是占位值 `__UNI__NOTE_MANAGER`。
- **影响**：同步回仓库时会覆盖占位值；若同伴直接使用仓库配置，关联服务空间仍会出问题。
- **建议**：与同伴确认统一使用真实 appid，或把 appid 放进本地忽略配置（需评估 uniCloud 关联方式）。

## 二、宏观总体问题

### M1 云服务未接入，数据不持久化
- **状态**：未解决
- **现象**：`uniCloud-alipay/cloudfunctions/` 为空，前端全部读取 `src/data/demo.js`；编辑页保存只弹提示。
- **影响**：新增、编辑、点赞、收藏等操作刷新即丢失，无法完成真实业务闭环。
- **建议**：按阶段 2 关联服务空间并实现云函数 CRUD，再替换演示数据。

### M2 数据库 schema 未上传，用户、索引与权限体系缺失
- **状态**：未解决
- **现象**：`notes.schema.json` 已定义字段与权限规则，但未上传；未定义索引；`uni-id-users` 表与 uni-id 配置尚未建立。
- **影响**：`auth.uid` 权限规则无法生效，登录与「仅作者可改删」无法验证；列表与推送查询缺少索引，数据量上来后会变慢。
- **建议**：上传 schema 后同步建用户表，为 `shared` / `category` / `owner_id` / `created_at` 设计索引，先跑通登录再验证读写权限。

### M3 页面交互多为占位，缺少真实业务逻辑
- **状态**：未解决
- **现象**：搜索仅提示「待接入」；共享广场点赞 / 收藏 / 关注无点击事件；我的页入口全部提示「功能待接入」且统计数字硬编码；编辑页不保存、无编辑回填；AI 入口仅提示预留；无登录态与路由守卫。
- **影响**：演示时只能展示界面，无法体现增删改查与权限控制，功能性评分（60 分）会受影响。
- **建议**：阶段 2–4 优先打通「登录 → 列表 → 详情 → 编辑 → 发布 → 分享」主链路，其余交互按时间取舍。

### M4 工程化缺口
- **状态**：未解决
- **现象**：目前未见统一的请求错误处理、加载态 / 空态、数据校验提示和测试配置。
- **影响**：弱网、失败场景体验差；后期问题定位成本高。
- **建议**：接入云函数时同步加统一响应封装、loading / empty 组件与关键流程自测清单。

### M5 AI 能力待定，范围需明确

- **现象**：`工作流.md` 写「AI 暂定不接入」；架构图列出二次创作（思维导图 / 笔记整理 / OCR）、调用方式（开发者 API / 自费 API）与模型选择，但均未实现。
- **影响**：不阻塞主线；若汇报时表述不清，容易被认为「承诺了但没做」。
- **建议**：明确「预留设计、不纳入本次交付」；在报告与 PPT 中用一页说明调用方式与后续计划。

### M6 文档与仓库指引需同步
- **状态**：未解决 · 低优先级
- **现象**：仓库 README 的「导入本文件夹中的项目文件」与本地实际结构、以及尚未确定的同步方式不完全一致；新增的指令集与 AI_LOG 未同步到仓库。
- **影响**：新成员或同伴上手时容易放错目录；仓库缺少协作文档。
- **建议**：同步方案确定后一并更新 README，并把 `指令集/` 纳入版本管理。

### M7 设计资料尚未落地

- **现象**：`color.md`（JetBrains 配色）与 `color2.md`（蓝 / 绿色系）是参考色册，页面目前使用的是自定义的 `#536cf1` 等颜色；架构图要求的 threeui 风格尚未系统应用。

- **建议**：阶段 1 收尾时确定主色、语义色与组件规范，统一到 `uni.scss` 和页面样式。

### M8 答辩代码理解与 AI_LOG 一致性
