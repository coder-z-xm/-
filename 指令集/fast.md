# 快捷指令 · fast.md

> 用法：在对话需求末尾追加关键词（可多个，空格分隔），Claude 在完成主任务后执行对应动作。
> 关键词需独立成词，建议大写。除 `GIT` 外，其他关键词**与 git 的 push 无关**，不会自动提交或推送代码。
> 组合出现时按 `UP → PUSH → PRB → GIT` 顺序执行（`GIT` 放在最后，确保文档更新一并提交）。
> 作业要求提交 `AI_LOG.md`（位于项目根目录 `AI_details/`）：`UP` 会同步维护它，单独补录或只记录 AI 使用时用 `AILOG`。

---

## UP —— 修改后更新记录

**含义**：完成本次修改后，自动更新 `指令集/log.md`、`指令集/problem.md` 和 `AI_details/AI_LOG.md` 的必要部分。

**执行内容**：
- `指令集/log.md` 顶部新增一条记录：时间戳（`YYYY-MM-DD HH:mm`）、修改内容概括、涉及文件、修改的代码部分、思路总结 / 决策变化。
- `指令集/problem.md`：登记本次改动引入或暴露的问题；已解决的问题标记为「已解决」。
- `AI_details/AI_LOG.md`：按作业六要素追加一条：任务 → 用的工具 → 提示要点 → AI 给出的方案 → 哪里错了 / 哪里不可靠 → 最终怎么改；补充涉及文件与记录人。信息缺失时写「待补充」，不编造。
- 只记录必要信息，不整段复制代码或提示词原文。
- 如果本次没有实际修改（只是咨询），不新增 log 条目，并说明原因；仍可更新 `指令集/problem.md` 与 `AI_details/AI_LOG.md`。

---

## AILOG —— 更新 AI 使用记录

**含义**：只更新 `AI_details/AI_LOG.md`，不改代码、不改其他文档。

**执行内容**：
- 按作业六要素追加或补录条目：任务、用的工具、提示要点、AI 给出的方案、哪里错了 / 哪里不可靠、最终怎么改。
- 补充涉及文件、记录人（多人协作时必填）。
- 用于补录历史会话，或在不产生代码修改时单独记录一次 AI 使用。
- 工具、提示或错误细节缺失时标注「待补充」，不要猜测。

---

## PUSH —— 更新阶段清单

**含义**：同步更新 `指令集/stage.md`，反映当前宏观进度。

**执行内容**：
- 已完成事项勾选为 `[x]`，未完成事项保持 `[ ]` 并**加粗突出**。
- 更新文件顶部的「当前阶段」与「下一阶段」。
- 不修改业务代码，不操作 git。

---

## PRB —— 更新并汇报问题

**含义**：更新 `指令集/problem.md`，然后读取该文件并向用户汇报当前存在的问题。

**执行内容**：
- 根据项目当前状态更新 `指令集/problem.md`：新增问题、合并重复项、关闭已解决项。
- 随后读取文件，按优先级列出**当前未解决**的问题及建议。
- 不修改业务代码，除非用户另外要求。

---

## GIT —— 同步到 GitHub 仓库

**含义**：将本地代码自动提交并推送到 GitHub 仓库。

**默认目标**：`https://github.com/coder-z-xm/-/tree/main/ZHIXU`
即仓库 `coder-z-xm/-` 的 `main` 分支、`ZHIXU/` 目录。如果用户特别说明其他仓库、分支或目录，以说明为准。

**执行内容**：
1. 确认 `origin` 指向默认仓库（`https://github.com/coder-z-xm/-.git`），目标为 `main` 分支的 `ZHIXU/` 目录。
2. 推送前先 `git fetch origin`，确认没有需要合并的远端新提交；有冲突时停止并询问，禁止强制覆盖。
3. 把本地 `zhixuLink` 的项目内容同步到仓库的 `ZHIXU/` 目录（不是仓库根目录）。
4. 生成提交（提交信息概括本次改动，必要时附上 `指令集/log.md` 的摘要）并推送到 `main`。
5. 汇报提交 hash、推送结果与仓库链接；失败时说明原因，视网络情况重试。

**注意**：
- 只同步项目文件，不带 `unpackage/`、`.hbuilderx/` 等忽略项。
- 不推送 `.env`、密钥等敏感文件。
- 本地目录与仓库 `ZHIXU/` 子目录尚未建立直接映射（见 `指令集/problem.md` P1）；首次执行前需先确定同步方案，或由用户指定映射方式。

## 使用示例

- `完成笔记列表的云函数 CRUD UP`
- `完成笔记编辑页接云 UP PUSH GIT`
- `补录历史 AI 使用记录 AILOG`
- `PRB`
- `先只检查问题，不要改代码 PRB`
- `同步到默认仓库 GIT`
- `同步到 feature/login 分支的 ZHIXU 目录 GIT`

---

## 约定

- 除 `GIT` 外，`UP` / `AILOG` / `PUSH` / `PRB` 都不代表 `git commit` / `git push`；是否提交、是否推送由用户明确指示。
- `GIT` 是唯一会提交并推送的指令；推送前必须先 fetch，确认无冲突，禁止强制覆盖远端。
- `AI_details/AI_LOG.md` 是作业提交材料，条目必须由组员核对；缺失信息标注「待补充」，禁止编造工具、提示或错误。
- 多个关键词同时出现时，按 `UP → PUSH → PRB → GIT` 顺序执行。
- 关键词对项目所有成员通用，新成员直接在本文件查看定义即可。
- 阶段或问题发生较大变化时，即使没有关键词，也建议主动提醒用户是否执行 `PUSH` / `PRB`。
