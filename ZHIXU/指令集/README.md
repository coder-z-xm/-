# 指令集 · 协作说明

本文件夹存放项目协作所需的文档，供项目成员和 Claude 共同维护。指令、进度、问题和修改记录都以这里为准。

## 文件说明

| 文件 | 作用 | 维护方式 |
| --- | --- | --- |
| `fast.md` | 快捷指令集（UP / AILOG / PUSH / PRB / GIT） | 手动维护 |
| `AI_details/AI_LOG.md` | AI 使用日志，作业要求提交的材料之一 | `UP` 自动追加，`AILOG` 单独补录 |
| `stage.md` | 宏观阶段清单，标明当前阶段与下一阶段 | `PUSH` 指令更新 |
| `problem.md` | 当前改动遗留的问题 + 宏观总体问题 | `UP` / `PRB` 更新 |
| `log.md` | 每次修改的时间戳、概括、涉及文件、思路与决策 | `UP` 指令更新 |

`AI_details/` 位于项目根目录（与 `指令集/` 同级），专门存放 AI 使用记录；`AI_LOG.md` 是该目录中需要提交的文件。

## 怎么用

1. 先读 `fast.md`，了解关键词的定义。
2. 向 Claude 提需求时，在末尾加上关键词，例如：
   - `实现首页搜索 UP PUSH`
   - `补录刚才的 AI 使用记录 AILOG`
   - `完成后同步到仓库 GIT`
   - `检查一下当前问题 PRB`
3. 关键词可以组合，执行顺序为 `UP → PUSH → PRB → GIT`；`AILOG` 可单独使用。

## 关键词速览

- `UP`：更新 `log.md`、`problem.md` 与 `AI_details/AI_LOG.md`（修改记录 + 问题 + AI 使用留痕）
- `AILOG`：只更新 `AI_details/AI_LOG.md`，用于补录或单独记录一次 AI 使用
- `PUSH`：更新 `stage.md`，勾选已完成事项，突出未完成事项
- `PRB`：更新 `problem.md`，并汇报当前存在的问题
- `GIT`：提交并推送到 GitHub 仓库（默认 `main` 分支的 `ZHIXU/` 目录）

## 作业硬性要求（来自《期末大作业 2026》）

- 必须提交 `AI_LOG.md`，逐条记录：**任务 → 用的工具 → 提示要点 → AI 给出的方案 → 哪里错了 / 哪里不可靠 → 最终怎么改**。
- 最终提交 4 项材料并打包为一个文件：演示文稿 PPT、完整源码、项目报告 PDF、AI-Log。
- 汇报时间：第 15/16 周（12.16 / 12.24），全员到讲台，需真机演示。
- 提交截止：**2027 年 1 月 3 日**，迟交无成绩。
- 答辩可能现场解释任意代码，严禁提交自己看不懂的代码。

## 约定

- 只有 `GIT` 会执行 git 提交和推送，其余关键词都不会。
- `AI_details/AI_LOG.md` 的条目提交前必须由组员核对，工具、提示与错误描述不编造。
- 文档随项目进度更新；重要改动即使没有加关键词，也建议补记录。
- 敏感信息（密钥、`.env` 等）不写入文档，也不同步到仓库。
